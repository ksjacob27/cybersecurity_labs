📝 Task 1: Network Connectivity Check with Bash Script

This task guides you through building a Bash script (autopinger.sh) to evaluate the status of the Metasploitable (VM-T) machine using ping. You will incrementally construct the script, explain each component, and analyze connectivity and latency results.

🔹 Step 1: Find VM-T IP Address

Log into the Metasploitable VM (VM-T) and run the following:

🔹 Step 2: Create Your Script

On the Kali (VM-D), create and open a script file:

Now start building the script step-by-step.

🔹 Step 3: Start the Script and Define the Target 

#!/bin/bash

VM_T_IP="192.168.10.6"

This defines the IP address of the Metasploitable VM (update it with the actual value you found earlier). The #!/bin/bash line tells the OS to run this script using Bash.

🔹 Step 4: Capture Ping Output 

ping_output=$(ping -c3 $VM_T_IP | tail -2)
ping_summary=$(echo "$ping_output" | head -n1)
ping_rtt=$(echo "$ping_output" | tail -n1)
  • Sends 3 ICMP Echo requests to VM_T_IP.
  • Uses tail -2 to extract the final two summary lines from the ping output.
  • ping_output now contains:
    • Line 1 → packet transmission/loss summary
    • Line 2 → round-trip time (RTT) statistics
  • ping_summary stores the first line (packet loss).
  • ping_rtt stores the second line (rtt min/avg/max/mdev).

🔹 Step 5: Extract Packet Loss 

has_errors=$(echo "$ping_summary" | grep -o errors)

if [ "$has_errors" != "" ]; then
    loss=$(echo "$ping_summary" | cut -d"," -f4 | cut -d" " -f2)
else
    loss=$(echo "$ping_summary" | cut -d"," -f3 | cut -d" " -f2)
fi

This handles two scenarios:

  • If the ping reports errors (host unreachable), the script extracts packet loss from a different column.
  • cut is used to isolate the correct field.

🔹 Step 6: Extract Minimum Delay 

delay=$(echo "$ping_rtt" | cut -d"=" -f2 | cut -d"/" -f1)

This extracts the minimum round-trip time (RTT) from the delay line. Example format:

rtt min/avg/max/mdev = 0.423/0.436/0.451/0.012 ms

🔹 Step 7: Evaluate the Results 

if [ "$loss" = "100%" ]; then
    echo "Server is not responding at all."
elif [ "$loss" != "0%" ]; then
    echo "Server is responding with packet loss."
else
    delay_sec_part=$(echo "$delay" | cut -d"." -f1)
    if [ "$delay_sec_part" -lt 1 ]; then
        echo "Server is responding normally."
    else
        echo "Server is responding slowly."
    fi
fi

This block interprets the results:

  • 100% loss → No response
  • Partial loss → Network issue
  • High delay → Network is slow

🔹 Step 8: Make and Run the Script

In the terminal:

chmod +x autopinger.sh
./autopinger.sh

📝 Task 5: Verifying MAC Address Integrity Using ARP

In this task, you will extend your autopinger.sh script to check that the MAC address of a target host matches its expected hardware address. This helps detect ARP spoofing attacks, where a malicious host impersonates another on the local network.

🔹 Step 1: Add the arpcheck Function

Append the following function to your script:

arpcheck() {
    target_ip=$1
    expected_mac=$2

    # Ensure ARP cache is populated
    ping -c1 $target_ip > /dev/null 2>&1 

    actual_mac=$(arp $target_ip | tail -1 | cut -c34-50)

    timestamp=$(date)

    if [ "$actual_mac" != "$expected_mac" ]; then
        echo "$timestamp - WARNING: Server with IP $target_ip is responding with wrong MAC $actual_mac" >> $logfile
        echo "$timestamp - WARNING: Server with IP $target_ip is responding with wrong MAC $actual_mac"
    else
        echo "$timestamp - Server $target_ip has valid MAC address $actual_mac" >> $logfile
        echo "$timestamp - Server $target_ip has valid MAC address $actual_mac"
    fi
}

🔍 Step 2: Explanation of the Command 

actual_mac=$(arp $target_ip | tail -1 | cut -c34-50)

Breakdown:

  • arp $target_ip: Displays the ARP table entry for the given IP.
  • tail -1: Ensures the last line is taken, in case there are multiple entries.
  • cut -c34-50: Extracts character positions 34 to 50, which typically contain the MAC address (format may vary by system/font).

✅ Consider testing arp manually first to verify the cut positions are correct for your setup. If needed, use a field-based cut:

arp -n $target_ip | awk '{print $3}'

📝 Task 7: Advanced Port Compliance Verification

In this task, you will enhance your script with a new version of the portcheck function. It will now receive a semicolon-separated list of expected open TCP ports, check if each is open, and verify that no other unexpected ports are accessible. This simulates a basic compliance audit to detect unauthorized services.

🔹 Step 1: Define the Enhanced portcheck Function

Add or update the following function in your script:

portcheck() {
    target_ip=$1
    expected_ports=$2
    IFS=';' read -r -a arrayports <<< "$expected_ports"

    # Scan all ports with nmap and store results
    nmaplog=$(nmap $target_ip)

    # Check each expected port is open
    for port in "${arrayports[@]}"
    do
        match=$(echo "$nmaplog" | grep "$port/tcp" | grep open)
        if [ -z "$match" ]; then
            echo "$(date) - Port $port on server $target_ip is EXPECTED to be open, but it is CLOSED or FILTERED." >> "$logfile"
            echo "$(date) - Port $port on server $target_ip is EXPECTED to be open, but it is CLOSED or FILTERED."
        fi
    done

    # Extract all actual open TCP ports from the scan
    allOpenPorts=$(echo "$nmaplog" | grep open | grep tcp | cut -d'/' -f1)

    # Check for any unexpected open ports
    for port in $allOpenPorts; do
        if [[ ! " ${arrayports[@]} " =~ " ${port} " ]]; then
            echo "$(date) - UNEXPECTED open port $port found on server $target_ip" >> "$logfile"
            echo "$(date) - UNEXPECTED open port $port found on server $target_ip"
        fi
    done

    IFS=$' \t\n'  # Reset IFS
}

📝 Task 8: Comprehensive Network Compliance Check from File Input

In this final task, you will implement the comprehensivecheck function. It reads an input file containing host IPs, expected MAC addresses, and allowed TCP ports. For each entry, it will:

  1. Check network availability (pingtest)
  2. Verify the MAC address (arpcheck)
  3. Audit port compliance (portcheck)

This provides a basic but realistic foundation for building automated compliance or asset verification tools.

🔹 Step 1: Create the Input File

In your project directory, create a file named input.txt with the following format:

192.168.10.6,00:0c:29:bc:e8:3b,139;445;21
192.168.10.7,00:0c:29:aa:bb:cc,80;22

Each line has:

  • IP address of a host
  • Its expected MAC address
  • A semicolon-separated list of ports that are allowed to be open

🔹 Step 2: Define the comprehensivecheck Function

Add the following function to your autopinger.sh:

comprehensivecheck() {
    input_file=$1

    while IFS=',' read -r ip mac ports
    do
        echo "$(date) - Starting compliance check for $ip"
        echo "$(date) - Starting compliance check for $ip" >> $logfile

        pingtest "$ip"
        arpcheck "$ip" "$mac"
        portcheck "$ip" "$ports"

        echo "---------------------------------------------------" >> $logfile
    done < "$input_file"
}

🔹 Step 3: Call the Function

At the bottom of your script, add:

comprehensivecheck input.txt

Make sure input.txt is in the same directory as your script or adjust the path accordingly.
